# เงื่อนไขและพฤติกรรม: กรณี “ยังไม่ผูกลูกค้า” แต่ยังสามารถเพิ่ม/ผูกข้อมูลได้

เอกสารนี้อธิบายกติกาและพฤติกรรมของหน้าต่าง “เมนูเพิ่มเติม” (Bottom Sheet) ของห้องแชท เมื่อลูกค้ายังไม่ถูกผูกกับห้องแชท ผู้ใช้ยังสามารถทำงานบางอย่างได้ เช่น ปักหมุด, เปลี่ยนสถานะ, เพิ่มผู้ดูแล (เซล) หรือผูก Job Card เป็นต้น โดยระบบจะจัดเก็บข้อมูลในเอกสารห้องแชท (chatroom) แทนเอกสารลูกค้า จนกว่าจะมีการผูกลูกค้าในภายหลัง

เอกสารนี้สามารถนำไปใช้เป็นเนื้อหาบนหน้าเว็บหรือคู่มือได้ทันที

---

## คำจำกัดความ
- ห้องแชท (Chatroom): เอกสารที่เก็บข้อมูลการสนทนาในเส้นทาง `workspaces/{workspaceId}/chatrooms/{chatroomId}`
- ลูกค้า (Customer): เอกสารลูกค้าในเส้นทาง `workspaces/{workspaceId}/customers/{customerId}`
- Job Card: เอกสารการ์ดงานในเส้นทาง `workspaces/{workspaceId}/cards/{cardId}`
- การ “ผูกลูกค้า”: การเติมค่า `customerId` (และอาจมี `customerName`) ในเอกสารห้องแชท เพื่อระบุว่านี่คือห้องของลูกค้ารายนั้น

---

## ตารางสรุปความสามารถเมื่อ “ยังไม่ผูกลูกค้า”

| ฟีเจอร์ | ใช้ได้โดยไม่ผูกลูกค้า | ที่จัดเก็บข้อมูล | หมายเหตุ |
|---|:--:|---|---|
| เปิด/ปิดบอทตอบกลับอัตโนมัติ | ✅ | chatrooms.bot_status | เขียนเป็น `'Y'`/`'N'` |
| เปลี่ยนสถานะห้อง (กำลังดำเนินการ/สำเร็จ) | ✅ | ผ่าน callback และ/หรือ chatrooms.chatroom_status | UI อัปเดตเรียลไทม์จากเอกสาร |
| ปักหมุดห้องแชท | ✅ | chatrooms.chat_pin | `'Y'`/`'N'` |
| เพิ่ม/ลบเซล (ผู้ดูแล) | ✅ | chatrooms.assignees | ถ้ายังไม่ผูกลูกค้า ให้เก็บที่ห้องแชท |
| เพิ่ม/ดูโน้ต | ❌ | – | ต้องผูกลูกค้าก่อน ระบบจะถามให้เลือกลูกค้า เมื่อสำเร็จจึงเปิดหน้าโน้ต |
| เพิ่ม/เปลี่ยนลูกค้า | ✅ | chatrooms.customerId, chatrooms.customerName | ผูกสำเร็จแล้วจะรีเฟรชเซล/แฮชแท็ก |
| จัดการแฮชแท็กลูกค้า | ❌ | – | แสดงเฉพาะเมื่อผูกลูกค้าแล้ว เพราะแฮชแท็กอยู่ในเอกสารลูกค้า |
| ผูก Job Card | ✅ | chatrooms.jobCardId, chatrooms.jobCardTitle | ถ้ายังไม่ผูกลูกค้า ระบบจะพยายามดึงลูกค้าจาก Job Card แล้วผูกให้อัตโนมัติ |
| เปิดรายละเอียด Job Card | ✅ | – | ต้องผูก Job Card แล้วเท่านั้น |
| เปลี่ยนชื่อ/รีเซ็ตชื่อห้องแชท | ✅ | chatrooms.name, chatrooms.original_name | เก็บชื่อเดิมใน `original_name` สำหรับรีเซ็ต |
| ลบห้องแชท | ✅ | – | ตามสิทธิ์ผู้ใช้/นโยบายระบบ |

---

## พฤติกรรมรายละเอียดตามฟีเจอร์

### 1) บอทตอบกลับอัตโนมัติ
- สลับสถานะได้เสมอ (ไม่ขึ้นกับลูกค้า)
- บันทึกที่ `chatrooms.bot_status` เป็น `'Y'` หรือ `'N'`

### 2) สถานะห้องแชท (กำลังดำเนินการ/สำเร็จ)
- เปลี่ยนได้เสมอ
- UI ฟัง event เรียลไทม์จากเอกสาร เพื่อ sync สถานะ

### 3) ปักหมุดห้องแชท
- ใช้ได้เสมอ โดยบันทึกที่ `chatrooms.chat_pin` เป็น `'Y'`/`'N'`

### 4) ผู้ดูแล (เซล)
- เพิ่ม/ลบได้เสมอ
- กรณี “ยังไม่ผูกลูกค้า” ➜ เก็บใน `chatrooms.assignees`
- กรณี “ผูกลูกค้าแล้ว” ➜ เก็บใน `customers/{customerId}.assignees`

### 5) โน้ต (Notes)
- ต้องมี `customerId` ก่อนเท่านั้น
- หากยังไม่ผูกลูกค้า เมื่อกด “โน้ต” ระบบจะแสดงตัวเลือกให้เลือก/ผูกลูกค้าก่อน

### 6) ผูก/เปลี่ยนลูกค้า
- ใช้ได้เสมอ
- เมื่อเลือกได้แล้ว จะบันทึก
  - `chatrooms.customerId = <pickedCustomerId>`
  - ถ้ารู้ชื่อ ➜ `chatrooms.customerName = <name>`
- หลังผูกสำเร็จ ระบบจะ
  - โหลด assignees จากเอกสารลูกค้าแทนห้องแชท
  - แสดงแผงจัดการแฮชแท็กลูกค้า
  - (ถ้าไม่มี Job Card) พยายามค้นหา Job Card ล่าสุดของลูกค้ารายนั้นมาเชื่อมให้โดยอัตโนมัติ

### 7) แฮชแท็กลูกค้า
- แสดงเฉพาะเมื่อมี `customerId`
- โหลดรายการแฮชแท็กทั้งหมดใน workspace (scope: `customer`) + สถานะแฮชแท็กของลูกค้าปัจจุบัน
- เมื่อผู้ใช้แก้ไข ➜ บันทึกที่ `customers/{customerId}.hashtags` เป็นรายการวัตถุ `{id,text,color}`
- “เพิ่มแฮชแท็กใหม่” จะสร้างแฮชแท็กใน workspace ก่อน แล้วค่อยผูกให้ลูกค้า

### 8) Job Card
- สามารถผูก Job Card ได้แม้ยังไม่ผูกลูกค้า โดยบันทึก
  - `chatrooms.jobCardId`
  - `chatrooms.jobCardTitle`
- ถ้ายังไม่ผูกลูกค้า ระบบจะพยายามอ่าน `customerId`/`customer` จาก Job Card แล้วผูกลูกค้าให้อัตโนมัติ (ถ้าพบ)
- แตะบัตรที่ผูกไว้เพื่อเปิดรายละเอียดการ์ด

### 9) เปลี่ยนชื่อ/รีเซ็ตชื่อห้องแชท
- เปลี่ยนชื่อ: บันทึก `chatrooms.name`
- รีเซ็ต: นำ `chatrooms.original_name` (ถ้าเคยเก็บไว้) มาใส่กลับใน `name`

## โครงสร้างข้อมูลที่เกี่ยวข้อง (Firestore)

### chatrooms (workspaces/{workspaceId}/chatrooms/{chatroomId})
- `bot_status: 'Y' | 'N'`
- `chat_pin: 'Y' | 'N'`
- `chatroom_status: 'IN_PROGRESS' | 'DONE'` (แล้วแต่ระบบส่วนกลาง)
- `assignees: string[]` (ถ้ายังไม่ผูกลูกค้า)
- `customerId?: string`
- `customerName?: string`
- `jobCardId?: string`
- `jobCardTitle?: string`
- `name?: string` (ชื่อแชทปัจจุบัน)
- `original_name?: string` (ชื่อเดิม — ใช้รีเซ็ต)

### customers (workspaces/{workspaceId}/customers/{customerId})
- `assignees: string[]` (กรณีผูกลูกค้าแล้ว)
- `hashtags: Array<{ id: string; text: string; color: string }>`

### cards (workspaces/{workspaceId}/cards/{cardId})
- `customerId?: string`
- `customer?: { id?: string; name?: string }`
- `title?: string` หรือ `name?: string`

## ฟลว์สำคัญ

### A) เพิ่มโน้ตเมื่อยังไม่ผูกลูกค้า
1) ผู้ใช้กด “โน้ต”
2) ระบบตรวจพบว่าไม่มี `customerId` ➜ เปิดตัวเลือกให้ “เลือก/ผูกลูกค้า”
3) ถ้าผูกลูกค้าสำเร็จ ➜ เปิดหน้าโน้ตของลูกค้ารายนั้น
4) ถ้ายกเลิกหรือยังไม่มีลูกค้า ➜ ยุติการเปิดโน้ต พร้อมเตือนในแถบด้านบน

### B) ผูก Job Card ขณะยังไม่ผูกลูกค้า
1) ผู้ใช้เลือก Job Card
2) ระบบบันทึก `jobCardId`/`jobCardTitle` ใน chatroom
3) ถ้า chatroom ยังไม่มี `customerId` ➜ อ่านจากการ์ด ถ้าพบ `customerId` ➜ ผูกลูกค้าให้โดยอัตโนมัติ

### C) เพิ่ม/ลบผู้ดูแล (เซล)
- ถ้ามี `customerId` ➜ แก้ไขใน `customers/{customerId}.assignees`
- ถ้าไม่มี `customerId` ➜ แก้ไขใน `chatrooms.assignees`

---

## ข้อควรระวัง/Edge Cases
- สิทธิ์การเขียน (Permissions): ผู้ใช้ต้องมีสิทธิ์พอในการแก้ไขเอกสารที่เกี่ยวข้อง ไม่เช่นนั้นจะขึ้นแจ้งเตือนข้อผิดพลาด
- ข้อมูลเรียลไทม์: UI ฟังการเปลี่ยนแปลงจาก `chatrooms` เพื่อ sync สถานะ ปักหมุด บอท และการผูกลูกค้า/การ์ด
- แฮชแท็กใหม่: ถ้าผู้ใช้ใส่รหัสสีผิดรูปแบบ ระบบจะ fallback เป็นสีมาตรฐาน เช่น `#f97316`
- ชื่อลูกค้า/การ์ด: หากไม่พบชื่อในเอกสาร ระบบจะแสดงสถานะ “กำลังดึงชื่อ…” และพยายามโหลดเพิ่มเติม

## ตัวอย่าง Payload ที่ระบบบันทึก

### 1) ผูกลูกค้ากับห้องแชท
```json
{
  "customerId": "cust_abc123",
  "customerName": "บริษัท เอ บี ซี จำกัด"
}
```

### 2) เพิ่มเซลเมื่อยังไม่ผูกลูกค้า
```json
{
  "assignees": ["user_01", "user_02"]
}
```

### 3) ผูก Job Card
```json
{
  "jobCardId": "card_789",
  "jobCardTitle": "ติดตั้งระบบกล้องโครงการ X"
}
```

### 4) แฮชแท็กลูกค้า (บนเอกสารลูกค้า)
```json
{
  "hashtags": [
    {"id": "vip", "text": "VIP", "color": "#f97316"},
    {"id": "followup", "text": "FollowUp", "color": "#60a5fa"}
  ]
}
```

## เกณฑ์ความสำเร็จ (Acceptance Criteria)
- เมื่อยังไม่ผูกลูกค้า:
  - ผู้ใช้สามารถ ปักหมุด/ปลดปักหมุด, เปิด/ปิดบอท, เปลี่ยนสถานะห้อง ได้สำเร็จ
  - ผู้ใช้สามารถเพิ่ม/ลบเซลได้ โดยระบบแก้ไขที่ `chatrooms.assignees`
  - ผู้ใช้สามารถผูก Job Card ได้ และถ้าการ์ดมีลูกค้า ระบบจะผูกลูกค้าให้อัตโนมัติ
  - การเปิด “โน้ต” จะบังคับให้เลือก/ผูกลูกค้าก่อน
- เมื่อผูกลูกค้าแล้ว:
  - แสดงแผงแฮชแท็กของลูกค้า และแก้ไขได้ โดยบันทึกที่เอกสารลูกค้า
  - การเพิ่ม/ลบเซลจะย้ายไปแก้ไขที่ `customers/{customerId}.assignees`

---

## คำแนะนำการแสดงผลบนเว็บ
- แยกส่วน “ข้อมูลห้อง” (pin/bot/status) ออกจาก “ข้อมูลลูกค้า” (แฮชแท็ก/เซล/โน้ต) ชัดเจน
- ในสถานะยังไม่ผูกลูกค้า ให้เน้นปุ่ม “เพิ่มลูกค้า” และ “ผูก Job Card”
- เมื่อผูกลูกค้าแล้ว แสดงชื่อ/อวตารตัวอักษร และแผงแฮชแท็กอย่างชัดเจน
